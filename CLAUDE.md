# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, installable PWA collection of standalone developer tools (base converter, JWT debugger, JSON diff, chmod calculator, etc.), built with plain HTML/CSS/JS — no framework, no bundler for app code. Each tool lives at `tools/<tool-id>/` as a self-contained mini-app (`index.html`, `script.js`, `style.css`, `data.js` where needed, `favicon.svg`) and is also reachable as a clean route (e.g. `/chmod-calculator`) generated at build time.

## Commands

```bash
npm ci                       # install (Playwright only devDependency)
npx playwright install chromium

npm run build                 # regenerate precache-manifest.js + build dist/
npm test                      # build, then: syntax check, static check, unit tests, precache check, e2e (Chromium)

npm run test:syntax           # node --check on all JS
npm run test:static           # third-party asset integrity / static checks
npm run test:unit             # node --test tests/*.test.mjs
npm run precache:check        # verify precache-manifest.js is current (fails if stale)
npm run precache              # regenerate precache-manifest.js

npm run test:e2e              # build dist/ then run full Playwright suite
npm run test:e2e:built        # run Playwright against an already-built dist/ (no rebuild)
```

Run a single Playwright spec (after `npm run build`, or against an already-running server with `BASE_URL`):

```bash
npx playwright test tests/tools/chmod-calculator.spec.js
npx playwright test tests/regression.spec.js -g "some test name"
```

Local dev server (no build needed for basic manual testing, but routes like `/chmod-calculator` only exist in `dist/`):

```bash
python3 -m http.server 8000    # open http://127.0.0.1:8000, tools reachable at tools/<tool-id>/
```

Playwright's own webServer serves `dist/` on port 4173 — don't hand-run a server on that port while tests are active.

## Architecture

**Source vs. build output.** The repo root (`index.html`, `app.js`, `styles.css`, `tools/`) is the dashboard shell and hand-written tool source. `dist/` is fully generated by `scripts/build-site.mjs` — never edit it directly. The build:
- Copies public assets (via `scripts/public-assets.mjs`).
- Downloads and pins (SHA-384) third-party libraries referenced by tools into `dist/vendor/`, then rewrites HTML to reference the local copies (`scripts/external-assets.mjs`) — the deployed site has no runtime CDN dependency. The build throws if any unvendored `https://` script/link tag survives.
- Generates one HTTP-200 route per tool from `tool-catalog.js` plus `sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt`, and per-tool metadata/JSON-LD (`scripts/seo.mjs`).
- Regenerates the service worker precache inventory (`scripts/precache.mjs` / `generate-precache-manifest.mjs`).
- Stamps a cache version — CI uses the GitHub Actions run number; local builds use a committed fallback unless `CACHE_VERSION=<n>` is passed (`scripts/cache-version.mjs`).

**`tool-catalog.js` is the single source of truth** for tool routes, names, descriptions, and capabilities. It drives the dashboard's search/listing (`app.js`), the generated SEO/discovery files, and per-route page generation. Adding a tool without registering it here means it has no route, no sitemap entry, and doesn't appear on the dashboard.

**Shared tool layer** (`tools/main.css` under `@layer shared`, `tools/main.js`) provides cross-tool components: dropdowns (`.dd`, `data-dd`), the icon sprite (`#dt-icon-sprite` / `#i-<name>` symbols), the split resizer (`data-resize`), toasts (`DevToolsMain.showToast`), and modals (`data-modal`). Full contract and rationale for each is in `tools/style-guide.md` — read it before touching shared UI, since it documents *why* each behavior exists (e.g. focus trap on modals, async focus retry, toast timing). Because `shared` is a CSS layer, a tool's own stylesheet always wins on specificity ties, so `main.css` only sets appearance (color, radius, border, shadow, type) — layout/sizing stays tool-local. Never reimplement a shared component locally; use the hooks.

**Service worker** (`sw.js`): network-first for navigations (so deploys show up promptly), stale-while-revalidate for static assets. `precache-manifest.js` is generated — after adding/removing public files, run `npm run precache` and commit the updated manifest, or `npm run precache:check` will fail CI.

## Testing structure

- `tests/regression.spec.js` — pins specific past bugs; add a case here when fixing a regression.
- `tests/tools/*.spec.js` — one file per tool, walks that tool's advertised capabilities from `tool-catalog.js` so a removed/broken feature fails loudly. Also covers shared components directly (`dropdown.spec.js`, `modal.spec.js`, `toast.spec.js`, `resizer.spec.js`, `icons.spec.js`, `fields.spec.js`, `typography.spec.js`, `icon-buttons.spec.js`).
- `tests/helpers.js` — shared Playwright helpers; always open tool pages via `openTool(page, tool)`, which disables analytics/service worker for the test, makes clipboard writes observable, and fails the test on any console error or uncaught page exception.
- `tests/*.test.mjs` — Node's built-in test runner (not Playwright) for build-script-level unit tests (cache version, external assets, SEO, runtime hygiene).
- Playwright config caps workers at 4 locally / 2 in CI deliberately — higher worker counts saturate the static file server and produce flaky click/fill timeouts.

## Adding a tool

1. Create `tools/<tool-id>/` with `index.html`, `script.js`, `style.css` (and `data.js`/`favicon.svg` as needed), loading `../main.css` and `../main.js`.
2. Register it in `tool-catalog.js` (route, name, description, capabilities) — this alone wires up the dashboard, SEO output, and route generation.
3. Reuse shared components from `tools/main.css`/`main.js` per `tools/style-guide.md` rather than writing local equivalents.
4. Add `tests/tools/<tool-id>.spec.js` covering the tool's capabilities.
5. Run `npm run build && npm test` before committing.
