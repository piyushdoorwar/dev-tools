Choosing a status code

The classes

  • 1xx — the exchange is still in progress.
  • 2xx — it worked.
  • 3xx — look somewhere else.
  • 4xx — the caller has to change something.
  • 5xx — the server has to change something. Only 5xx should page you.

The pairs people get wrong

  • 401 means unauthenticated; 403 means authenticated but not allowed.
  • 400 means unparseable; 422 means parsed but invalid.
  • 301/302 may rewrite POST to GET; 308/307 never do.
  • 429 blames the caller; 503 blames the server. Both should carry Retry-After.
  • 404 hides whether a thing exists; 410 confirms it existed and is gone.

Two rules worth keeping

  • Never return 200 with an error in the body. Caches, retries, and alerting all read the status line, not your JSON.
  • Reserve 500 for things you did not anticipate. A predictable failure returned as 500 is an alert that wakes someone for nothing.

Definitions follow RFC 9110, which replaced RFC 7231 and RFC 2616 in 2022. Non-standard codes from nginx and Cloudflare are labelled as such.
