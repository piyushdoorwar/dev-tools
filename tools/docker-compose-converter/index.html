Conversion notes

    What gets converted

    Input

    • Paste any number of docker run, docker container run, docker create or podman run commands. Each becomes a service, named after --name or the image.
    • Commands are read the way a shell would read them: quotes, escapes, and line continuations with \ (Bash), ` (PowerShell) or ^ (cmd).
    • Other commands such as docker network create are skipped.

    Output

    • The file follows the current Compose Specification, so it has no version: line. Docker Compose v2 ignores that key.
    • Named volumes and user-defined networks are declared at the top level. --link, --volumes-from and --network container: between converted services become depends_on.
    • $VAR stays as it is, and Compose fills it in from your environment or .env, just as the shell did. A $ the shell would have kept literal (inside single quotes, or escaped) becomes $$.
    • $PWD in a bind mount becomes ., because Compose resolves relative paths from the compose file's folder.
    • --gpus becomes a deploy.resources device reservation.

    Conversion notes

    • Flags with no Compose equivalent, such as -P or --cidfile, and flags the converter does not recognise are listed below the output. They are never dropped silently.
    • Flags that only affect your terminal (-d, --rm, --attach) are left out on purpose.
