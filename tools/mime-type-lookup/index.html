Content-Type pitfalls

Searching

  • Type an extension (.webp), a filename (archive.tar.gz), a media type, or a whole header (text/html; charset=utf-8). Parameters you type are echoed in the detail and carried into the copied header.
  • Exact extension and type matches come first, then prefixes, then types whose notes mention the word. The list headings say which is which.
  • Press ↓ to move into the list and ↑ / ↓ to browse. The selected type is kept in the address, so a link such as #image/webp opens on it.

Content-Type mistakes that actually ship

  • Text without a charset. Send text/html; charset=utf-8. Without it the browser guesses the encoding, and a wrong guess shows mojibake.
  • X-Content-Type-Options: nosniff stops the browser from guessing a type from the bytes. Scripts and stylesheets with the wrong type are then refused outright, so the type has to be right.
  • text/javascript, not application/javascript. RFC 9239 (2022) made text/javascript the standard; the application/ form is obsolete but still works.
  • .ts is two things: an MPEG transport stream (video/mp2t) and TypeScript source. Many server type maps pick video, so raw TypeScript arrives as a video.
  • image/jpg is not a type. The subtype is always jpeg, whatever the file is called.
  • application/json has no charset parameter. JSON between systems must be UTF-8 (RFC 8259), so ; charset=utf-8 is ignored.

Headers and servers

  • Content-Type is not Content-Encoding. Compression on the wire keeps the real type and adds Content-Encoding: gzip. A .gz download is application/gzip with no encoding header.
  • Let the browser set multipart boundaries. When you send FormData with fetch, leave Content-Type unset.
  • An nginx types { } block replaces the inherited map in that context. Add lines to mime.types, or include it first.

A curated list of common types, not the whole registry. The authority is the IANA Media Types registry; types marked unregistered are de facto names IANA has never registered. An extension is a hint, not a check of what the file contains.
