Using this reference

What is here

  • Syntax — character classes, anchors, quantifiers, groups, lookaround, flags, replacement strings, and the traps that cost the most time.
  • Patterns — ready-to-use expressions with the samples they do and do not match. The test suite runs every pattern against those samples, so what the card claims is what the regex does.

Working with the tester

  • Test it on any pattern card opens the Regex Tester with that pattern, its flags, and its sample lines already loaded.
  • The tester links back here from its cheat sheet, so you can move between reference and experiment without losing your place.

Before you ship a pattern

  • Validation is rarely a regex problem alone. An email pattern catches typos; only a confirmation email proves the address exists.
  • Escape anything a user typed before putting it inside new RegExp().
  • Watch for nested quantifiers over overlapping sets — (a+)+ shapes can hang on hostile input.

Everything is the JavaScript (ECMAScript) flavour. Where PCRE, Python or Ruby differ in a way that matters, the syntax rows say so.
