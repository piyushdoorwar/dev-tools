    How this works
    
                    
                
    
                
    
                    
    
                        
    Base64 is not encryption. Anyone who sees a Basic header can read the password, so only send it over HTTPS. Nothing is saved or sent anywhere: the header and snippets are built in this tab.
    
                    
    
                    
      
                        
    • Basic (RFC 7617) is base64(username:password) encoded as UTF-8. A username cannot contain a colon; a password can, because decoding splits at the first colon.
      • 
                        
    • Bearer (RFC 6750) tokens are sent as-is. Tokens outside the b64token alphabet get a warning, but whitespace and control characters are refused. JWTs show their alg and expiry.
      • 
                        
    • API key goes in a header (default X-API-Key) or, if the API expects it, a query parameter, which changes the URL in every snippet.
      • 
                        
    • Decode accepts Authorization: Basic …, Basic … or Bearer …, and can load the result back into the form.
      • 
                        
    • Snippets: curl and HTTPie are single-quoted for a POSIX shell (a quote becomes '\''); fetch uses JSON string literals. Extra header names must be RFC 7230 tokens.
