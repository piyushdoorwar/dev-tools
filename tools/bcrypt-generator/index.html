About bcrypt

Everything runs locally. Passwords and hashes never leave this tab.

Cost factor

  • The cost is a power of two: cost 12 runs 212 = 4,096 rounds of the key schedule, and each step up doubles the time.
  • OWASP recommends at least 10. Pick the highest cost your login path can afford — typically a few hundred milliseconds on your server. This page runs in JavaScript, so a native library will be several times faster than the time shown here.

Versions

  • $2b$ is the current OpenBSD prefix and the default in most libraries.
  • $2a$ is the older prefix, still produced by Java and Node's bcryptjs. $2y$ is PHP's. For any password under 255 bytes, all three compute the same hash, so the prefix only affects which systems accept it.

The 72-byte limit

  • Bcrypt only uses the first 72 bytes of the password (in UTF-8). Anything after that is ignored, so two long passwords that share a 72-byte prefix have the same hash. The tool warns you when this happens.

Hash layout

  • $2b$10$ then 22 characters of salt, then 31 characters of hash — 60 characters in total, in bcrypt's own Base64 alphabet (./A–Za–z0–9).
  • The salt is random for every hash, so hashing the same password twice gives two different strings. Both verify.
