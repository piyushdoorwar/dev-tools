How parsing works

Splitting

  • The URL is split with the generic pattern from RFC 3986 (appendix B) into scheme, authority, path, query and fragment. Nothing is normalised, so rebuilding it gives back exactly what you pasted.
  • Relative references such as /search?q=x and bare query strings such as a=1&b=2 work too.
  • Normalized shows what a browser would actually request: lower-cased host, default port dropped, .. resolved, and unsafe characters percent-encoded. International hosts are shown in their punycode form.

Editing

  • Edit the URL, a component, or a parameter; the other two update as you type.
  • Parameter keys and values are edited decoded and encoded for you. Parameters you haven't touched keep their original encoding.
  • Untick a parameter to leave it out of the URL without losing it. Editing the URL text directly re-reads the table, which drops unticked rows.
  • Repeated keys such as tag=a&tag=b are kept as separate rows, in order. Copy as JSON turns them into an array.

+ is space

  • On (the default), + decodes to a space and spaces encode as +, matching HTML forms and URLSearchParams.
  • Off, + is a literal plus and spaces encode as %20, as RFC 3986 treats them.
