How it works

Everything runs locally. Keys come from your browser's WebCrypto API and never leave this tab.

Algorithms

  • RSA uses e = 65537. The key is generated for signing (RS256), but the key material is the same for RSA-PSS or RSA-OAEP — only the JWK alg hint differs. Choose 3072 or larger for keys that must last past 2030; 4096 can take a few seconds.
  • ECDSA P-256, P-384 and P-521 map to ES256, ES384 and ES512.
  • Ed25519 is the modern default for SSH and signatures (EdDSA). X25519 is for key agreement only, so it has no SSH form. Both need a recent browser; unsupported ones are disabled.

Formats

  • PKCS#8 (BEGIN PRIVATE KEY) and SPKI (BEGIN PUBLIC KEY) are what OpenSSL, Node, Java and Go read.
  • JWK output carries a kid set to the RFC 7638 thumbprint: SHA-256 over the required members in sorted order, base64url encoded.
  • The OpenSSH line goes straight into authorized_keys. The comment is only a label and can be edited without regenerating.
  • The private key is not offered in OpenSSH's own format. OpenSSH reads the PKCS#8 PEM directly: save it as id_ed25519 with chmod 600, or run ssh-keygen -p -f key.pem to add a passphrase and rewrite it. ssh-keygen -y -f key.pem prints its OpenSSH public key, and ssh-keygen -i -m PKCS8 -f public.pem converts an RSA or ECDSA SPKI PEM (older OpenSSH releases reject Ed25519 there).

Fingerprints

  • The SSH fingerprint matches ssh-keygen -lf key.pub: SHA256: plus unpadded Base64 of the key blob's SHA-256.
  • The SPKI fingerprint is Base64 SHA-256 of the DER public key — the value used for certificate and HTTP public key pinning (pin-sha256).
