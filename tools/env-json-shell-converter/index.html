How conversion works

Reading .env

  • One KEY=value per line. Blank lines, # comments, and a leading export are ignored.
  • Unquoted values are trimmed and end at #. Single-quoted values are literal. Double-quoted values understand \n, \t, \", \\, and \$. Both kinds of quote may span several lines.
  • A repeated key keeps its last value, as dotenv does.

Reading shell

  • Understands export A=1 B=2, bare A=1, declare -x, fish set -gx A 1, and PowerShell $env:A = '1', with shell quoting rules: single quotes are literal, double quotes only escape \" \\ \$ \`.
  • Other commands, such as echo or FOO=1 npm start, are skipped and counted. $(…) is kept as text, never run.

Variable references

  • With Expand on, $VAR, ${VAR}, and ${VAR:-default} resolve against keys defined earlier in the input, the way Docker Compose, Vite, Next.js, and source read them. Single-quoted values are never expanded. Nothing is read from your real environment.
  • With it off, references are kept as literal text.

Writing

  • Values are quoted only when they need it, so the output always reads back to exactly the same value. Shell output uses single quotes, so nothing in a value is expanded when you paste or source it.
  • JSON input accepts an object of KEY: value pairs or a Kubernetes/ECS-style [{"name": …, "value": …}] list. Numbers and booleans become text, null becomes empty, and nested objects are written as JSON text.
  • Keys that the target cannot hold, such as my-key in Bash, are skipped and counted rather than written as a broken line. In PowerShell, setting a variable to an empty string removes it.
