How it works

                    
                

                

                    

                        
Everything runs locally. Text, passwords and keys never leave this tab; encryption uses the browser's WebCrypto.


                        
Algorithm

                        
    
                            
  • AES-256-GCM with a random 12-byte IV and a 16-byte authentication tag. GCM is authenticated: a wrong password or a single changed byte is detected, never silently decrypted into garbage.
    • 
                            
  • The key comes from your password via PBKDF2-HMAC-SHA-256 with a random 16-byte salt. 600,000 iterations is the OWASP 2023 recommendation; 310,000 was the 2021 figure. Every message gets a fresh salt and IV, so encrypting the same text twice gives different output.
    • 
                            
  • The password is encoded as UTF-8 exactly as typed (no Unicode normalisation).
    • 
                            
  • Raw key skips PBKDF2 and uses a 256-bit key you supply as 64 hex characters or Base64. Use it when a machine holds the key; use a password when a person has to remember it.
    • 
                        


                        
Compact format, version 1

                        
    
                            
  • One Base64 or Base64url string of these bytes: version (1) = 0x01 · kdf id (1) · iterations (4, uint32 big-endian) · salt (16) · IV (12) · ciphertext · tag (16).
    • 
                            
  • kdf id 1 = PBKDF2-HMAC-SHA-256. kdf id 0 = raw key; its iterations are 0 and its salt is 16 zero bytes. Changing a header byte either changes the derived key or makes the header invalid, so tampering with it is caught too.
    • 
                            
  • The Envelope tab shows each part in hex, and Interop has Python and Node.js code that decrypts this format.
    • 
                        


                        
JSON envelope

                        
    
                            
  • {"v":1,"alg":"A256GCM","kdf":"PBKDF2-SHA256","iter":600000,"salt":…,"iv":…,"ct":…,"tag":…}, with the binary fields in the chosen alphabet. A raw-key envelope has "kdf":"none" and no iter or salt.
    • 
                            
  • Decrypt detects the format (compact or JSON) and the alphabet (Base64 or Base64url, padded or not) on its own.
    • 
                        


                        
Errors

                        
    
                            
  • Authentication failed: the password or key is wrong, or the data was changed. GCM cannot tell the two apart, by design.
    • 
                            
  • Truncated: fewer bytes than the 50 a version-1 token needs, or Base64 whose length cannot be complete.
    • 
                            
  • Unknown version: the first byte is not 1, so it was not made by this format.
    • 
                        


                        
Ciphers left out on purpose

                        
    
                            
  • RC4: its keystream is measurably biased and plaintext can be recovered; RFC 7465 bans it from TLS.
    • 
                            
  • Rabbit: a stream cipher with little public cryptanalysis and no integrity check. It survives mainly because CryptoJS ships it.
    • 
                            
  • Triple DES: its 64-bit block falls to birthday attacks such as Sweet32 once one key has encrypted a few tens of gigabytes, and NIST disallowed it for encryption after 2023.
    • 
                            
  • AES-CBC without a MAC: an attacker can flip plaintext bits and use padding-oracle attacks, and a wrong password often "decrypts" to garbage instead of failing. CryptoJS's passphrase mode adds a one-round MD5 key derivation on top.
