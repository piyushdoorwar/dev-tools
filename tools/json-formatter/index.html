JSONPath RFC 9535

  • Selectors: .name ['name'] [0] [-1] [0,2] [1:3] [::2] * ... Filters use @ for the current item, $ for the root, and == != < <= > >= && || !.
  • The leading $ is optional. Switch to Paths to see where each match lives.

jq a practical subset

  • Supported: | , ( ), .a.b .[] .[1:3] .. ?, array and object construction, + - * / %, comparisons, and or not, //, if … elif … else … end, try … catch, … as $x |, reduce, and = |= += -= *= /= //=.
  • Builtins include select map map_values keys has length type add any all sort sort_by group_by unique_by min_by max_by to_entries from_entries with_entries paths del walk flatten range limit first last join split test capture sub gsub ascii_downcase tostring tonumber tojson fromjson.
  • Not supported: def, foreach, label, destructuring, modules, and input/inputs. A query that yields several values prints one per line, like jq.

Why "diff-friendly"

  • Key order is kept exactly as written. JSON.parse moves keys that look like numbers ("10", "2") to the front, which reshuffles a file and pollutes the diff. This formatter doesn't.
  • Numbers are written back exactly as they appear. 12345678901234567890 stays that way instead of becoming 12345678901234567000, and 1.50 stays 1.50.
  • Sort keys gives every object a stable alphabetical order, so two dumps of the same data diff cleanly no matter how they were produced. Duplicate keys are flagged, because only the last one survives.
