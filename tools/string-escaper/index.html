Escaping Reference

Everything runs locally.

Escaping makes text safe to drop inside a literal. It is not a substitute for parameterised queries or argument arrays when those are available.

Slug
Each line becomes one slug. Accents are stripped (é → e), a few letters are spelled out (ß → ss, & → and), apostrophes are dropped, and every other run of punctuation or spaces becomes the separator. Unicode keeps non-Latin letters instead of dropping them. Max trims at a word boundary where it can.
JSON
Escapes " \ and control characters as \n \t \u0000. The result is also a valid JavaScript string. \uXXXX additionally escapes everything above U+007E, emitting surrogate pairs for emoji.
SQL
Standard doubles single quotes (O''Brien), which is all PostgreSQL, SQLite, SQL Server and Oracle need. MySQL uses backslash escapes for \ ' " \0 \n \r \Z, matching mysql_real_escape_string.
Shell
Single quotes are the safest POSIX form: nothing inside is special, and a literal ' becomes '\''. Double escapes \ " $ `, but interactive bash may still expand !. ANSI-C ($'…', bash and zsh) can spell newlines and control characters. Unescaping splits the input into words, one per line, and never expands variables.
Regex
Escapes exactly the syntax characters \ ^ $ . * + ? ( ) [ ] { } | and optionally /. That set is valid in JavaScript even with the u flag, and in PCRE, Python, Go and Java.
HTML Attribute
Escapes & " ' < >, so the value is safe in single- or double-quoted attributes. &#10; also encodes newlines and tabs, which XML parsers otherwise normalise to spaces.
